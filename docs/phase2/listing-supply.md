# 매물 수 증감 (핵심 지표 B)

코드: `scripts/listing_supply.py` (매일 파이프라인 6-3 단계, 공표 게이트 다음) · 테스트: `tests/test_listing_supply.py`
출력: `site/data.json` → `market.listingSupply`, `history.sqlite3` → `leading_indicator_panel`

## 산출 규칙
- **대상:** 고정 표본 110개 단지 중 그날 품질 판정이 VALID인 단지의 매도 매물입니다. 매물 ID는 하루 안에서 중복을 제거합니다.
- **공표 가능일:** 아래 세 조건을 모두 충족한 날입니다(NEGO와 같은 기준).
  - VALID 단지 105개 이상
  - 공표 유예일(11-12, 11-13)이 아님
  - 첫 검증 기준선(11-14) 이후
- **증감(전일·7일·28일):**
  - 두 날짜 모두 VALID인 단지만으로 계산하고, 공통 단지가 105개 미만이면 증감률을 공표하지 않습니다.
  - 자치구 증감은 그 구의 표본 단지 전부가 공통일 때만 공표합니다.
- **관측 종료:** 사라진 매물 ID입니다. 거래 완료로 보지 않습니다.
- **ID 변경 제외:** 같은 단지·면적·층·가격으로 새 ID가 나타나면 ID만 바뀐 같은 매물로 보고 신규·관측 종료 모두에서 뺍니다. 공표는 순수 신규·순수 관측 종료만 합니다. 네이버 매물 ID가 자주 바뀌어 원시 ID 기준 건수는 의미가 없습니다.
- **관측 시각:** 날마다 첫·마지막 관측 시각(KST)과 수집 구분(SCHEDULED / RERUN / OFF_SCHEDULE)을 기록하고, 증감에는 관측 간격(시간)을 함께 기록합니다.
- **추이 그래프:** 공표 가능일을 이어 붙인 동일 단지 연쇄 지수입니다(첫 공식일 = 100). 연결 변화가 없으면 선을 끊습니다.
- **NEGO × 매물 조합:** 서울은 `negoIndex.changes[h]`, 자치구는 `spreadDynamics.districts[d].changes[h]`의 공표된 변화와 매물 증감률을 짝지어 Q1~Q4 또는 FLAT으로 기록합니다. 신호로 해석하지 않습니다.

## 선행성 검증 준비 (아직 검증 전, 예측 산출 없음)
`leading_indicator_panel`(day × scope[서울 all / 자치구 코드] × horizon[level/1d/7d/28d])에 아래 값을 쌓습니다.
- NEGO 수준·변화
- 매물 수
- 공통 단지 수
- 매물 증감
- 조합
- 공표 여부와 사유

이 표를 국토부 실거래 원장의 월별 가격과 자치구·월로 결합해 다음 가설을 검증합니다.
1. 매물 증가가 실거래가격 하락에 앞서는가
2. 매물 감소가 실거래가격 상승에 앞서는가
3. NEGO와 매물을 결합하면 단일 지표보다 설명력이 높은가
4. 자치구별로 선행 시차가 다른가

실거래가격이 월 단위이므로, 의미 있는 검증에는 최소 수개월 치 일별 관측이 필요합니다.
